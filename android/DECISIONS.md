# HITOP for Android: decisions the agent made

Choices `android/GOAL.md` doesn't cover, each with its reason. The owner may overrule any of them.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-23 | **The whole request pipeline runs in Rust** (hitop-core through hitop-ffi): prepare (variables, auth, GraphQL/form bodies, send rules), pre/post scripts, HTTP (reqwest + rustls: timings, cookies, redirects, digest, OAuth client credentials, SigV4), the runner and the reports. Kotlin keeps the UI, storage, the HITOP Cloud REST client and Android platform code. | There is no HitopKit for Kotlin; a port would be a second implementation of behaviour that must match hitop-core byte for byte. With the FFI the app sends exactly what the CLI sends. |
| 2026-11-23 | **Script engine: boa through hitop-ffi** (hitop-core `scripting`, the shared `pm-shim.js` it packages). | Follows from the row above (GOAL allows boa "if that is simpler"); no QuickJS binding to maintain, same engine as the CLI and the desktop. |
| 2026-11-23 | **hitop-ffi calls SyncFFI's operations** (`hitop-sync-ffi` as a path dependency, `call_json` for every op it doesn't own) instead of copying them. | One implementation of the sync plan, folder format, hitop-sync-crypto glue and gRPC ops for both apps. |
| 2026-11-23 | JNI: one `Native.call(byte[] op, byte[] args): byte[]`, UTF-8 bytes both ways; `jni` crate 0.21.1. | JNI strings are modified UTF-8 (NUL and emoji change); a unit test sends both. 0.21 is the widely used API (0.22 rewrote it) and is all this needs. |
| 2026-11-23 | compileSdk 37.2, targetSdk 37 (Android 17), minSdk 31. | GOAL: newest stable API; Compose 1.13 (BOM 2026.11.01) needs the 37.1+ platform. |
| 2026-11-23 | Toolchain: AGP 9.5.2 (built-in Kotlin), Kotlin 2.4.21, Gradle 9.9.2 (sha256-pinned wrapper), JDK 17, NDK r28c (28.2.13676358), cargo-ndk 4.1.2. | Newest stable releases on 2026-11-23; NDK r28 links 16 KB-aligned by default (CI checks it). |
| 2026-11-23 | Method colours are the Android drafts' (GET #4ADE80, POST #FBBF24, PUT #60A5FA, PATCH #C084FC, DELETE #F87171), not the web app's tokens iOS used. | The owner approved the Android drafts; GOAL says "method colors as in the drafts". |
| 2026-11-23 | Faint text is #8A869C instead of the drafts' #6F6B80. | #6F6B80 is about 3.6:1 on the code ground, under WCAG AA 4.5:1. |
| 2026-11-23 | Kotlin is split into `core` (plain JVM: models, storage, cloud, sync, runs) and `app` (Compose, Android). `core`'s tests run on the JVM against a host build of hitop-ffi. | Fast tests without an emulator, and the end-to-end tests against a real sync server run like iOS's `core` job. |
| 2026-11-23 | Instrumented UI tests run only in CI (`android.yml`, API 31 and 37 emulators). | The build machine has /dev/kvm but this user isn't in the kvm group, so no local emulator. |
| 2026-11-23 | TLS trusts the webpki roots only (as the CLI and the desktop): user-installed or corporate CAs and the system proxy aren't used. | hitop-core's client; same behaviour as every other HITOP client. Revisit if people ask. |
| 2026-11-23 | OAuth 2.0 authorization-code requests fail with hitop-core's message (it needs a browser on a loopback port); client credentials and password grants work. | hitop-core's `browser_sign_in` needs a terminal; iOS doesn't do it either. |
| 2026-11-23 | Gradle licence check: `app.cash.licensee` (Apache-2.0) on the app's runtime classpath, permissive SPDX ids only, exceptions named one by one with a reason. hitop-ffi joins `licenses.yml`'s cargo-deny matrix with the repo's deny.toml. | GOAL "Licences"; licensee fails the build on anything not allowed. |
| 2026-11-23 | `url` 2.5.8 → 2.5.9 in every Cargo.lock (RUSTSEC-2026-0592). | The advisory turned `licenses.yml` red on main the day A0 started; GOAL needs it green. |
| 2026-11-23 | `android.yml` runs on every push to main (no path filter, so a docs-only last commit runs it too), and pull requests that touch android/, SyncFFI, hitop-core, hitop-sync-crypto, spec, brand. | GOAL: the workflow must be green on main. |
| 2026-11-23 | The UI tests' "stub transport" is an in-process HTTP proxy (`core` StubServer) that hitop-core's client uses (`useHttpProxy` sets HTTP_PROXY before the client is built); the seeded shop-api hosts are `http://*.shop.example`. | The transport is hitop-core's (Rust), so the stub sits at the far end: requests still go through variables, auth, scripts, cookies and timings. https would need a fake certificate authority. |
| 2026-11-23 | The UI tests live in `app/src/sharedTest` and run twice: on the emulators (androidTest, CI) and under Robolectric 4.18.1 on the JVM (test, with the host hitop-ffi build, SDK 35, phone-sized screen). | No local emulator here; Robolectric gives minutes-long local feedback on the same tests. |
| 2026-11-23 | Backups and device transfers exclude everything (`data_extraction_rules.xml`, `allowBackup=false`). | Secrets are bound to this phone's keystore key and can't be restored elsewhere; the library syncs through HITOP Cloud instead. |
| 2026-11-23 | The launcher icon's monochrome (themed) layer is the white foreground layer itself. | It is the same pixels; one file per density instead of two identical ones (lint IconDuplicates). |
| 2026-11-23 | The editor's Code button generates code through hitop-core's `snippet` (curl, fetch, Python, Go, Java, Rust) in A1. | One FFI op over code that already exists; secrets stay `{{name}}`. |
| 2026-11-23 | A2–A7 were built in one working tree and land as one branch (`android-a2`) after A1 merges, with PROGRESS.md recording each tranche's tasks. | A1's emulator problems held its merge; the later tranches don't touch A1's behaviour, and one green run of every workflow for them saves hours of CI. |
| 2026-11-23 | UI tests talk to an in-memory `FakeCloud` (core `cloud/FakeCloud.kt`) that follows the sync server's shapes and rules; the real server is covered by core's `CloudEndToEndTest` (sign-in, library, conflicts, tombstones, devices, delete, a shared collection round trip with the CLI), required in CI. | Emulators can't run the Rust sync server; iOS does the same (FakeCloud + CloudEndToEndTests). |
| 2026-11-23 | Native Google sign-in: Credential Manager's Google ID token goes to new server routes `POST /v1/auth/google/native/{start,finish}` (nonce flow, audience = the Web client, `azp` must be one of `HITOP_SYNC_GOOGLE_ANDROID_CLIENT_IDS`). The app uses it only when it was built with a client id and the server lists `googleNative`; otherwise Google sign-in runs in a Custom Tab like GitHub and Apple. | GOAL: "Google native"; the server had only the browser flow. Deploying the server is an owner step. |
| 2026-11-23 | Shared collections reuse SyncFFI's ops (`SharedSync.kt` ports iOS SharedSync.swift); the published vectors (`hitop-sync-crypto/vectors`) run on the device (androidTest `VectorTest`) and on the JVM. | One crypto implementation; GOAL A3 "published vectors pass in instrumented tests". |
| 2026-11-23 | Runs: hitop-ffi `runStart/runNext/runCancel` over hitop-core's `run_step` and `ReportBuilder`; the app's report.json, JUnit and HTML are hitop-core's own bytes (core test compares with `hitop run`). The run lives in a `dataSync` foreground service with Stop. | GOAL A4 "report equals hitop-core's". |
| 2026-11-23 | Widgets are Glance (Last run, Failing, Pinned with Send) fed by a snapshot file of names and counts only (no URLs, no values); rendered in `glance-appwidget-testing` unit tests. | Nothing secret on the home screen; Glance's test harness is GOAL A4's "test harness". |
| 2026-11-23 | SSE requests read the stream live through hitop-ffi `sseStart/sseNext` without pre/post scripts; WebSocket and gRPC use hitop-core's clients (hitop-ffi `ws*`, SyncFFI `grpc*`, reflection only: no .proto files on the phone). | Same as the iOS app (I4); scripts have no meaning per event. |
| 2026-11-23 | On-device AI: ML Kit GenAI Prompt API (`com.google.mlkit:genai-prompt`, Gemini Nano through AICore), licence exception in licensee by URL (ML Kit terms, like Play services). Explain, suggested tests (kept only if they pass on the response), request from text; curl import needs no model. What the model sees is `ModelInput` (secrets masked, credentials removed, bodies cut). UI tests use `FakeAssistant`. | The only on-device model API on Android; GOAL A6. Its terms aren't an SPDX licence, like Google sign-in's. |
| 2026-11-23 | Layouts: one pane below 600 dp; list + request (response as a sheet) from 600 dp; list + request + response from 1200 dp (Material "large"). | At 840–1199 dp three panes left the request pane ≈170 dp wide (seen in the 7-inch store screenshot). |
| 2026-11-23 | Keyboard shortcuts at the app's root: Ctrl/Meta + Enter send (connect for WebSocket/SSE/gRPC), S save, K search, N new request. | GOAL A6; the web app's bindings where they exist. |
| 2026-11-23 | Accessibility: ATF checks (`enableAccessibilityChecks`) on the main screens on the emulators, a WCAG AA contrast unit test over every text token on every ground, layouts at 2× font scale and phone/foldable/tablet widths under Robolectric. Text-input dialogs became bottom sheets. | GOAL A6; AlertDialogs with text fields never went idle under Robolectric, and sheets match the drafts. |
| 2026-11-23 | Release: `isMinifyEnabled = false`; signing only from environment variables (CI decodes the upload keystore from a secret); AAB split by ABI; CI builds and checks a release AAB/APK with a throwaway key every run (`bundletool validate`, signature, both ABIs, 16 KB). Play uploads only by hand (`android-play.yml`, internal track, r0adkll/upload-google-play pinned by commit); `release-android.yml` attaches a signed APK + AAB to a GitHub Release on an owner's `android-v*` tag, never Latest. | GOAL A7; no shrinker rules to keep for the JNI bridge and JSON models (the APK is mostly the Rust library). |
| 2026-11-23 | Store pictures are rendered by a Robolectric test (`StoreScreenshots`) from the seeded sample at Play's sizes (phone 1080×1920, 7-inch 2880×1800, 10-inch 3840×2400, feature graphic 1024×500), JPEG; the phone's response shot draws the sheet's content full screen. | Reproducible from the code; Play refuses the 2.2:1 emulator captures and alpha channels; Robolectric can't capture a sheet's window. |
| 2026-11-23 | Licence exception: `org.reactivestreams:reactive-streams` 1.0.3 is CC0-1.0, allowed by name (not CC0 in general). It comes with ML Kit (`genai-prompt` → `kotlinx-coroutines-reactive`). | CC0 is a public-domain dedication with no conditions, looser than every licence GOAL lists; ML Kit is the owner's choice for on-device AI. |
| 2026-11-23 | Data safety declares ML Kit's diagnostics (device model, OS, app version, timings, error codes; a per-installation id) as collected, required, for analytics, not shared; the privacy policy says so. The release check fails if the app's native code holds the usage ping endpoint. | Google's ML Kit disclosure lists them for `genai-prompt`, and the app asks ML Kit for the model at every start. HITOP's own code sends nothing of the kind. |
| 2026-11-23 | Release version codes: minutes since 2026-01-01 in both release workflows (an input can override it in android-play.yml). | Separate run-number counters would give a tag build and a Play upload the same code; one clock always increases. |
| 2026-11-23 | Release workflows: the upload keystore and its passwords exist only inside the build step (decoded to the runner's temp directory, removed on exit); the Play upload action gets only the AAB and the service account file. | Least exposure for the upload key; the upload action is a third-party action (pinned by commit). |
| 2026-11-23 | API 37 UI tests run on the `aosp_atd` (test device) 37.0 image. | The AOSP 37.0 image's system_server aborted in task snapshots (a gfxstream assertion with every host renderer); the Google APIs 37.0 and 37.2 (16 KB) images kept the user locked so apps couldn't write files. The test-device image runs every test; API 31 stays on Google APIs. |
| 2026-11-23 | A JSON response's foldable lines are 48 dp tall controls named for screen readers ("total, 2 keys, folded"); other lines stay compact. | Accessibility checks on the device flagged 19 dp touch targets and an unnamed arrow. |
