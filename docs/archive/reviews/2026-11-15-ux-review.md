# HITOP UI/UX review (2026-11-15) and what was fixed (UX3)

A hands-on review of the live web app and the marketing site at 1440×900,
1024×700 and 390×844 (touch), signed out, plus a read of the source on main.
It found 30 things. This file lists each one with what was done about it.
The fixes are tranche UX3 in `HITOP_NEXT_UI.md`. Nothing is deployed and
nothing is released: that is the owner's call.

## Findings and their state

| # | Finding | State |
| --- | --- | --- |
| 1 | Cookies set on a redirect were lost and redirects were invisible | Fixed. hitop follows redirects itself (`hitop-core/src/redirects.rs`): each hop is reported, hop cookies reach the jar. The proxy returns `redirects` and takes `followRedirects`; the web app shows an "N redirects" chip and a Redirects tab, and the request has a Follow redirects switch. Same in the CLI (`hitop send --no-follow`, hops printed), the runner and the desktop command. |
| 2 | On a phone, tapping the last editor tab shifted the workspace sideways | Fixed. The tab strip scrolls on its own and `main` clips sideways overflow. Measured: `main` scrollLeft 68 before, 0 after. |
| 3 | The URL caret and selection drifted after every variable | Fixed. The mirror chip has no horizontal padding. Measured: 6 px per variable before, under 1.5 px after (e2e). |
| 4 | A missing variable gave only a toast | Fixed. A card in the response pane names the variable, with "Define" and "Open variables". |
| 5 | Scripts had no console; a throw lost its line and the earlier results | Fixed. Console tab, `line, column` on a thrown error, tests that ran before the throw are kept (web, desktop command, hitop-core). HitopKit only defines `console` so scripts that log don't fail there. |
| 6 | The site hid the Windows and Linux apps | Fixed. Download in the nav, the hero's second link goes to /download/, a "Windows and Linux" card on the home page. |
| 7 | On a phone the response landed below the fold | Already on main since UX2 (the response scrolls into view when it arrives); the review ran against the older deploy. |
| 8 | Phone tap targets under 44 px | Fixed for HITOP's own controls under `(pointer: coarse)`: icon buttons, tabs, tree row buttons, Import and Export, Pretty and Source. Fields and a few lit-material controls keep their height. |
| 9 | At 1024×700 the response body got a third of the screen | Partly. The status row keeps its icons (one row less; the body starts at y=329, was 361) and Save stays visible as an icon. The Pretty/Source toolbar was not moved onto the tab row. |
| 10 | Tab from the URL landed in a variable popover that stayed open | Fixed. The chip is out of the Tab order, the peek opens on click only and closes when focus leaves. |
| 11 | A URL without a scheme was refused when it had a space | Fixed in the shared rule (Rust, Swift, web; `spec/sending.md`, `spec/vectors/send.json`). |
| 12 | Opening a History entry added an unsaved request to the tree | Partly. A History entry opens in one preview tab that the next entry reuses until it is edited. Not done: the host in auto-names, "Clear unsaved". |
| 13 | "Open and run" did not run; no Run or Export in the collection menu | Fixed: Open, Run, Export…. |
| 14 | No auth or headers on a collection or folder | Fixed. Collection and folder defaults on the collection page, "Inherit from parent" is the default auth of a request, with a line saying where the value comes from. Honoured by `hitop run` and `hitop requests send`; format in `spec/collection-format.md` (`headers`, `folderDefaults`). |
| 15 | Rail pages hid the open tabs and Esc did not go back | Fixed with a "Back to <request>" bar on every page; Esc in a field blurs first, then returns. The tab strip is still hidden on pages. |
| 16 | No Beautify for the body | Fixed. Format for JSON (keeps `${variables}`) and XML. GraphQL is not formatted. |
| 17 | No Cookies tab on the response | Fixed, with a count. |
| 18 | No per-request settings; the time limit default is none | Partly. A Settings tab on the request (follow redirects, time limit; also in request files and the CLI). The proxy's 20 s limit is stated beside both settings. Not done: a distinct "stopped by the proxy" message; the default stays "none". |
| 19 | No bulk edit, no path parameters | Fixed. Bulk edit for params and headers; Path variables for `:name` segments (`pathVariables` in the format, honoured by the CLI). |
| 20 | No filter on a JSON response | Fixed. A JSONPath field with a result count. |
| 21 | Faint text failed 4.5:1 | Fixed. The faint token is `#8a8a96`, also on the site. Left: the `+` between keys (lit-material kbd, 4.17:1). |
| 22 | Focus rings differed by control | Partly. HITOP's own buttons, links and chips have one ring (2 px accent, 2 px away). Rings drawn inside lit-material components are fixed there. |
| 23 | Phone drawer rail had no labels; the environment was only in the drawer | Fixed. Labelled rail in the drawer, an environment chip in the phone top bar. |
| 24 | Get started and the storage card crowded the sidebar | Fixed. Get started folds to one line after the first step; the storage card shows its full text. |
| 25 | Type and spacing inconsistencies | Partly. Dialog headlines use Geist (missing type roles added), sizes are 11/12/13/14/16/18/28/30, delete dialogs lost the dead space. Not done: Name/Value headers on Environments, parameter headers on a phone, the import placeholder size. |
| 26 | Misleading wording in Tests and the response | Partly. Snippets use `pm.*` like the sample; the response toggle is Pretty/Source. Not done: failure messages still read as the assertion library writes them. |
| 27 | Keyboard hints on touch | Fixed under `(pointer: coarse)`. |
| 28 | The site showed no real picture | Partly. The hero is a real screenshot of the web app. No video loop. |
| 29 | Desktop builds are unsigned | Site only: /download/ leads with the web app and the CLI, the workaround steps sit in a details block. Signing and notarising need the owner's Apple and Windows certificates. |
| 30 | The phone site header lost the name | Fixed. Full-width header with the wordmark and a 44 px menu button. |

## Owner tasks

- Sign and notarise the macOS build and sign the Windows build (29).
- Deploy: the web app, the site and hitop-server go together. An older
  hitop-server ignores `followRedirects` and returns no `redirects`; the web
  app then behaves as before (final response only).
- Release the CLI and desktop when wanted: `--no-follow`, inherited auth and
  headers, request settings and path variables are in no released version.
- A real macOS or Windows desktop build was not made here (no GTK on the
  build host); CI builds it.

## Checks

- `webapp/tests/ux3.cjs` (in `npm run test:e2e`, web and desktop harness):
  redirect chip, chain and jar cookie, Follow redirects off, inherited auth,
  path variables, console, a throwing script, JSON filter, Format, the
  not-sent card, Back and Esc, the Cookies tab, a scheme-less URL with a
  space, mirror drift, no peek on Tab, History preview, no sideways shift
  and the environment chip on a phone.
- `webapp/tests/unit-ux3.mjs`, hitop-core tests for redirects, defaults,
  settings and path variables, `spec/vectors/send.json`.

Run on 2026-11-15 against a local hitop-server: the 33 e2e suites pass in web
and in desktop-harness mode (`next.cjs` timed out once in eleven web runs,
waiting for a response; `git.cjs` needs the `git-json` helper built, see
`tests/tauri-mock.cjs`), unit suites, `cargo test` for the CLI workspace and
the server, clippy as in CI, HitopKit tests, site build and check.
